> Cosoado Lab Blog 同時掲載: https://cosoado-lab.com/blog/peerconnect-lp-rewrite/

公開済みの LP を再読したら、自分が **2 つの「実装していない機能」を中心訴求にしていた** ことに気付きました。本稿はその発覚から、機能撤去 → 利用規約との整合性確認 → デザインを「お便りのような和風」に書き直すまで、6 分でまとめた振り返りです。個人開発で LP を書く全員に役立つはず。

---

## 何が起きていたか

[ピアコネクト](https://peerconnect.cosoado-lab.com) は希少がん・AYA 世代のがん・男性のがんなど、身近に同じ病気の方が見つかりにくい方のためのマッチングアプリ。ベータ公開直後の LP を読み直すと:

1. **夜のラウンジ** — 22 時から翌 5 時だけ開く匿名チャット
2. **先輩の道のり** — 同じがん種・治療法を経験した先輩の 3 年・5 年・10 年後が読める投稿欄

の 2 つを中心訴求にしていた。両方とも、コードベースを `grep` してもテーブル定義もハンドラもありません。**LP に書いた約束が、宙に浮いている**状態。

過去にも同じパターンで別アプリ (CosMate) の「ドタキャン防止 / 自動制裁」訴求を撤去した経験あり。教訓は明確で、

> **LP に書く中核訴求は、実装根拠を Phase 1 段階で必ず確認する。**

ここから LP を全面リライトしました。

---

## 撤去の選択肢 3 つ

未実装機能を LP から消す際、選択肢:

| 選択肢 | 採用度 |
|---|---|
| A. すぐに実装して LP の主張を真にする | △ (DB + モデレーション + UI で 2-3 週間かかる機能なら現実的でない) |
| B. LP からまるごと削除する | ◯ (撤去はすぐ可能) |
| C. 「準備中」セクションに格下げして残す | ◎ (撤去 + 透明性確保) |

採用は **B + C のハイブリッド**。ヒーロー / 機能カード / FAQ JSON-LD からは完全撤去し、LP の中盤に「**今あるもの・これからのこと**」セクションを新設して、未実装機能を分かりやすく分けました。

```text
今、お使いいただけるもの
  ・5 軸プロフィールで似た方をお探しになる機能
  ・双方が「いいね」されたあとのメッセージ機能
  ・匿名のアバター・プッシュ通知を送らない設計
  ・退会後にプロフィール・メッセージ・履歴を速やかにお消しする運用

これから検討してまいるもの
  ・経験された方の経過を、お読みになれる投稿欄
  ・がん種別の合言葉のような小さなしるし
  ・患者会さま・支援団体さまとの公式リンクのご紹介
```

「先にお約束だけを並べることはいたしません」と添えました。β 段階の小さなアプリにとって、誠実な期待値調整は登録動機に直結します。

## 利用規約・PP との食い違いを潰す

予定外に発覚したのが、**利用規約・プライバシーポリシーとの整合性**。

LP には「退会すると、すべてのデータが即時削除される」と書いてあった。一方プライバシーポリシー第 6 条には:

> 運営者は、利用目的の達成に必要な期間に限り個人情報を保存します。アカウント削除（退会）の請求があった場合、運営者は本人確認の上で **合理的な期間内** に当該アカウントの個人情報を削除するものとします。ただし、以下の情報については削除されない場合があります。
>
> - 法令により保存が義務付けられている情報
> - システムのバックアップに含まれる情報
> - 統計目的で匿名化・集計化された情報
> - 不正利用防止・係争対応のために合理的に必要な情報

LP は「即時 + すべて」、PP は「合理的な期間内 + 例外あり」で、**食い違い**。

[景表法 第 5 条第 1 号](https://laws.e-gov.go.jp/law/337AC0000000134#Mp-At_5)の優良誤認に該当する可能性のあるライン。LP 側を弱める方が安全:

> 退会後、プロフィール・メッセージ・履歴は速やかに削除されます (法令保存義務分・バックアップ世代を除く / プライバシーポリシー参照)。

教訓:

> **LP を書いたら、自分の利用規約とプライバシーポリシーを音読する。1 文ずつ食い違いを潰す。**

## デザインを「お便りのような和風」に切り替えた理由

リライト前は明朝体ベースで墨色と紺、夜空 SVG をヒーロー背景にした「夜の窓」モチーフでした。

問題:

- 夜空 SVG の重さが、がんの sensitivity と合わない
- カード・グリッド・3 つの機能セクションが、LP テンプレ感を残している
- 角丸 12-16px がモダン web デザインのままで、和の落ち着きが弱い

コンセプトを「**同じご病気の方へお書きする、一通の手紙**」に切り替えました。

| 要素 | Before | After |
|---|---|---|
| カラー | 墨 + 紺 + 夜空 | 和紙の生成り `#f7f0dd` + 墨 `#2a2520` + 落款の朱 `#a8503a` |
| 角丸 | 12-16px | 2-4px (障子・封筒の直線感) |
| shadow | カードに 4-12px | ほぼゼロ (和紙に影は似合わない) |
| アニメ | hover scale 1.02 + spring | scale 完全排除、opacity / 微 translate |
| ヒーロー装飾 | 夜空 SVG + 星 + 月 | 罫線一本 + 落款「絆」(右上に小さく) |
| 余白 | line-height 1.8 | line-height 2.0、padding 32-56px |

落款は SVG で擬似的に。フィルタで微妙に擦らせてあります:

```tsx
<svg width="68" height="68" viewBox="0 0 68 68">
  <rect x="6" y="6" width="56" height="56" rx="3"
    fill="none" stroke="#a8503a" strokeWidth="2.2" opacity="0.82" />
  <text x="34" y="44" fontFamily="'Hiragino Mincho ProN', serif"
    fontSize="34" fontWeight="700" textAnchor="middle"
    fill="#a8503a" opacity="0.88">絆</text>
  {/* 擦れの表現 (生成り色の薄い rect を重ねる) */}
</svg>
```

過剰装飾 (桜・鶴・水紋繚乱) は意図的に避けました。和風 LP は「やりすぎ」で安っぽくなるリスクがあり、ワンポイントの落款で「お便り」感を完成させるほうが、医療系の sensitivity と合います。

## 文言を「お医者さんが話すような優しい敬語」へ

並行して文言も全面書き直し。

**Before:**

> 同じ道を歩む人と、静かにつながる。
> 希少がんをはじめ、同じ病気・同じ治療段階の人を探せる場所。
> 比較しない、ランクしない。

**After:**

> 同じご病気の方と、静かなつながりを
> あなたと似た道を歩いてこられた方が、どこかにいらっしゃいます。
> ご身近に同じご病気の方がおられないとき、5 つの軸でゆっくりお探しになれる場所をご用意しました。

ポイント:

- **見出し / kicker / CTA ラベルは体言止め** で残す (短く印象的にしたいため)
- **本文・FAQ・founder voice は優しい敬語** に統一
- 「ご身近に」「もしよろしければ」「お一人お一人」「徐々にお集まりになっています」のような、お医者さんが診察室で話すトーン
- 強い断定 (「絶対」「即時」「完全」) を避ける
- 急かす表現 (「今すぐ」「今だけ」) も使わない

## アプリ内ロックアウト画面も同じトーンに

LP だけ和風にしても、登録後にダッシュボードへ飛んだ瞬間に通常 UI が出てくると、体験ギャップで「あれ？」となる。

ピアコネクトはベータで `betaDashboardLocked: true` のため、登録直後のユーザーは必ずロックアウト画面を見ます。ここを cancer 専用の `softMode` で和風に揃えました:

```tsx
{softMode ? (
  <>
    ご登録の方が、徐々にお集まりになっています。
    <br />
    お一人お一人とゆっくり出会えますよう、
    <br />
    もう少しだけお時間をいただけますと幸いです。
  </>
) : (
  <>
    ベータ版なので、コミュニティが育ったら順次解放します。
    <br />
    しばらくお待ちください。
  </>
)}
```

scale アニメも opacity に置換。「跳ねるボタン」は他ジャンルでは触覚アナログとして気持ちよくても、cancer では情緒的に重い。

## チェックリスト — LP を公開する前に

今回作った自己チェックリスト:

1. **未実装機能を訴求していないか** — LP の機能名で `grep src/` してヒットしない機能は撤去または「準備中」へ
2. **利用規約・プライバシーポリシーと矛盾していないか** — LP の主張ごとに PP の該当条文を引き、表現の幅 (即時 vs 合理的期間) を確認
3. **景表法・薬機法の優良誤認に該当しないか** — 「絶対」「完全」「即時」を機械的に検索
4. **ジャンル sensitivity に合うトーンか** — がん・AYA・男性がんに「跳ねるアニメ」「scale 1.05」「派手な色」は逆効果
5. **AI 感の排除パスを通したか** — `*LandingPage.tsx` の新規作成・大幅編集後は「さっきの AI 要素を排除して同じ要件で再作成」を自己実行
6. **LP の長尾 SEO を用意したか** — 単独の LP だけでは検索流入が薄い。`/guide` 配下のロングフォーム記事 (出典付き) を 3-5 本同時公開する

特に 1, 2, 3 はミスると致命的。優良誤認は[景表法 (不当景品類及び不当表示防止法) 第 5 条第 1 号](https://laws.e-gov.go.jp/law/337AC0000000134#Mp-At_5)の違反で、[消費者庁の指導対象](https://www.caa.go.jp/policies/policy/representation/fair_labeling/)になりえる。通信販売・有料サービスの広告は特商法第 12 条 (誇大広告等の禁止) でも別途規制対象になる。個人開発でも他人事ではない。
